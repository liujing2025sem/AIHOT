# 短讯选稿核验：业务闭环与验收任务

状态：工程实现任务。依据 `docs/LIVE.md` D-07、D-22、D-25、`docs/aihot-grill-decisions-20261103.md` 与现有短讯验收约定；不改变这些已经确认的决定。

## 要解决的运营问题

今日选稿按素材条数提示可以合成一期，但五条素材可能是同一事件的转载，也可能缺正文、过期或已经发布。运营需要在付费成稿前知道**初步可用的独立事件有几件**、哪个材料需要处理、下一步如何处理。

## 已收口的选择

1. 一期短讯选 5–12 条素材，至少五个独立、具备当前证据资格的事件；只能形成一篇待审合集。
2. 继续使用已经上线的事件身份、正文、来源、软件版本证据和 14/30 天新闻窗口；原文日期与新版本观察日期分别标识，不用采集时间冒充发布日期。
3. 选材检查只读取当前材料和发布记录，不建任务、不采集、不调用模型、不修改旧稿。运营手动勾选、移除、补齐材料，提交后才走既有队列。
4. 对确定性重复提供来源和处理建议，不自动确定主出处；不同标题、不同链接的语义重述仍可能在最终成稿环节被 HOLD。页面用“初步识别”表达这一边界。
5. 选材、审稿、交付各留在各自阶段。选材检查不碰现有版本、批准、原文保护、导出、WP 开关或私有业务配置。

## codebase-design：三种 interface 的比较

| 方案 | 调用者需要理解 | 主要成本 | 选择 |
|---|---|---|---|
| 单一只读选材检查 | 选中 ID → 资格报告 | 勾选变化后有一次短延迟读取 | 本轮采用 |
| 可扩展证据图 | 统一材料模型、关系图、不同场景的判断投影 | 当前只有一个真实消费者，抽象较多 | 待出现第二个消费者再评估 |
| 浏览器事件篮 | 候选指纹、缓存过期、本地计数与后台重验 | 两处需要维护判断结果，跨页同步复杂 | 吸收即时反馈和紧凑提示 |

选中的 **deep module** 对外只新增一个 `inspectBriefSelection(articleIds)` interface。后端将既有 `selectBriefEvents()` 的判断集中到共享的内部 evaluator，保证预检和提交共用相同证据规则。数据库继续使用已有可在测试中替换的读取依赖；前端通过管理员只读 GET 接入，不增加写入通道。

## 可验收的完整用户路径

1. 打开“今日选稿”，无需调用模型；选择 1–4 条仍可看已选情况，原逐条成稿流程不被短讯门槛挡住。
2. 继续勾选到 5–12 条，看到“已选数量、初步识别独立事件、其中可用独立事件、还差几件”。同一事件的多条资料只计一件。
3. 当材料重复、缺正文、无合格日期、超出 14/30 天、是参考资料或已公开时，逐条出现原因和真正可操作的建议；可在现有页面移除、补采或打开原材料核对。
4. 缺项处理后重新计算；未完成检查、存在问题或模型未就绪时清楚说明原因。最后点击“合成一期短讯”才产生任务。
5. 提交与 worker 在调用模型前继续读取当前 revision、原文、日期、事件身份和已发布记录；预检结果不能跳过这些门槛。已批准稿和旧页不得变化。
6. 验证跨页/筛选后选中材料仍归入同一份检查。取消、重新选择、较慢的旧响应不会覆盖新的选稿结果。

## 测试条件

- 纯函数：五个独立事件成功；六条素材有同事件重复；跨 URL/标题/正文/已有事件 ID 传递合并；1–4 条时仍能查看报告；正文缺失与时间问题同时可见。
- 政策：14 天和 30 天边界，软件新版本观察日期，首轮导入基线、已公开、未来日期、参考资料分别显示正确结果；`selectBriefEvents` 的既有成功和失败保持一致。
- 后台：检查只读且要登录；响应与选择中的 ID 对应，错误不会被当成就绪；创建时重新查验且不授予审批。
- 浏览器：1440、390、320 像素下正确显示计数、建议、键盘选材和焦点，选中不会触发付费或发布；网络失败提供重试。
- 外部真实业务：生产机器上真实 5 条独立 LED 新闻与首期英文审稿仍须单独验收，本任务的合成测试不能替代真实出稿效果。

## 范围外

不改数据库迁移、不新增模型层、不自动选主出处、不启用自动采集和 WordPress 发布、不重跑 6098/MiP、不引入新批量工作流、不建立与现有事件归组并行的第二套算法。
