01 / 每天的入口

打开以后，先做哪件事？

新消息、旧页变化、未完成稿如何排列？没有新增时，怎样让运营安心结束，而不必逐个页面找工作？

交付：一个主工作面，以及首次使用与日常使用的最短路径。

02 / 值得做的判断

这条材料应该变成什么？

短讯、解释文、旧页更新、参考资料、暂缓或不写。卡片必须让人直接看见变化、证据和处理理由。

交付：可行动的卡片；覆盖旧MiP资料、误配新闻、无日期新版本。

03 / 低负担审稿

怎样核对一次，就少做一次重复工作？

把证据核对与编辑判断组织清楚。改标题、数值或来源版本，分别影响哪些确认？受阻稿能否原地修改后继续？

交付：同一篇MiP“待修 → 核对 → 可交付”的三态原型。

04 / 可维护的内容

一条证据如何用于多处内容？

批准过的原厂声明可用于解释文和参考表；来源更正后，需要知道哪些已有页面受到影响，以及应改哪一句。

交付：一条MiP声明从采用、复用到修订的完整例子。

05 / 独立执行

外部Agent退出后，谁继续工作？

浏览器刷新、调用超时、付费结果已收到但尚未成稿，都应该有可理解的状态与恢复动作。

交付：人工触发独立运行、限定范围自动草稿的边界与异常交互。

06 / 创意的投入顺序

先做好哪一个有辨识度的能力？

版本追踪、参数解释、供应商询问清单、来源变化提醒，选一个先做。与同源、同模型、有上期摘要的定时任务比较。

交付：一个旗舰能力、一个明确舍弃的方向、一个业务验证样例。

运营不应重新购买一次模型结果

保存的Flash响应 → 修正别名与日期 → 导入候选 → 用户粘贴Claude编辑版 → 重算受影响问题 → 人工批准 → 导出。首篇小修可独立进行，不等整套设计。

只读回放：45处WARN → 30个聚合问题，其中26项重点、4项常规。并非目标机界面验收；编辑后须重新计算。

页面更新要能回答“改哪一句”

来源出现新版本 → 定位已采用的声明 → 列出关联稿件／页面 → 展示旧说法、新依据与建议修改 → 人确认 → 更新后回读。页面登记是这条链的前置。

这是需要设计的未来路径，不表示页面更新与回读已经完成。

“今天不用写”也是有价值的结果

区分没有新材料、只有重复材料、证据尚不完整、已有页面已经回答四种情况。告诉运营为何无须行动，保留可追溯依据。

设计评价看少翻了多少来源、少做了多少重复判断，不以卡片数量代替价值。
