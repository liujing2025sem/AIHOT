## 当前推荐：Agent 整理，人工做编辑判断

先用 WorkBuddy 当前 Agent 的文件接棒完成采编，不要求另开付费模型渠道。人先选题、再逐篇审稿、最后决定是否发布；系统保存原文版本、显示可定位的问题并阻止未满足条件的导出。分工与操作见 [human-editor-workflow.md](human-editor-workflow.md)。现有一键生成能力保留，Agent自评不能代替人工验收。

每稿不超过五项只是减负观察目标，不是验收或发布门槛，不能为达标删报、隐藏或合并本应分别处理的问题。当前仍为30档、每篇全审，所有WARN需确认；认证、商务、客户案例、新领域首篇逐字核对。

正文不完整：先补采，系统拒绝创建采编任务，不产生HOLD。正文完整但新闻价值或证据判断不足：进入任务后返回HOLD并保留理由。正文完整也不代表事实已经核实。

## 2026-11-01 内容规则、CAMOS与人工介入候选

WorkBuddy 2026-11-01现场回执已确认核心链路六项通过、一项说明需纠正（拒绝入任务而非HOLD）；这是回执时点结果，端口状态以当前目标实例探测为准。规则在服务端validateResponse之后、写入稿件之前执行；命中BLOCK将任务置blocked、不建立稿件，修改返回文件后可重新导入。WARN显示规则ID、字段与UTF-16字符区间；审核通过前必须显式确认，保存、审核、导出均重查。确定性规则并不等于语义完整性或法律核验；中文名、授权、完整中英等价等不确定问题只能WARN。

## 已有流程

本轮按用户要求使用统一管理员。登录后进入 /admin/studio；API配置在 /admin/channels。分角色权限暂缓。

1. 素材池默认展示正文可读的材料；可切换全部、待补正文、待核发布日期。标题进入原文阅读页，可补齐正文和日期。日期沿用信源中配置的规则，正文完整但缺日期也能处理；不会把采集时间当发布日期，也不会把“原文只有日期”显示成具体时分。
2. 可勾选1–12条材料，批量“补齐所选正文 / 日期”。筛选和翻页会保留选择，并可展开核对、逐条移除或清空。进度和逐条结果显示实际改善；“停止后续”会完成当前请求后停止，未处理的材料保持原样。失败、部分补齐和全部补齐分别显示，结果保存后可回看。已有完整正文、已有日期和补采期间发生的新版本不会被覆盖；该手动操作不调用付费抓取。
3. 所选正文完整后才可创建采编任务；指定可选目标页面。目标站点限Chipshow主站/美国站/欧洲站及Unishine。空目标按中立行业资讯。
4. 可下载单文件JSON交给Codex/Harness，内容包括原文版本、human-writing与公司规则、返回格式。将返回JSON导入相应任务，稿件写入数据库。重复导入同一结果不覆盖人工修改；原文版本或核实日期发生变化时拒绝旧结果。
5. 也可在原任务中点击“评估并成稿”（最多4条）。服务端读取当前渠道，通过原有预算和回执调用模型，校验引用后存为草稿。当前OpenCode Go只适用于编码；新闻生成需配置DeepSeek标准API或适合的兼容渠道。没有密钥/开关关闭时显示原因，不产生假稿。
6. 中文审稿、英文交付、原文证据、修改记录通过标签切换。保存使用版本检查，其他人已修改会提示刷新；保存已审核稿会撤销旧批准。切页/关页前提醒未保存修改。
7. 提交审稿→确认审核通过，或填写意见退回。审核通过可导出Markdown、HTML、JSON。这里的通过和导出不会自动发到公司官网。
8. 采集信源中可手动采集，最近一次的结果和失败原因会留在对应信源卡片，可点击重试、进入原生信源设置或新增来源。网络超时保留原材料与错误，不伪造新增。自动worker本轮未启用。

API配置保存到settings表；密钥在本机模型凭据文件。API生成开关实时读取持久化文件，独立进程可见。配置检测采用实际/models响应，404明确显示不支持列表；付费测试须由管理员明确点击。DeepSeek Pro禁用。

Windows运行包包含Node、PostgreSQL、安装依赖、源码、构建及初始化程序；不包含个人密码、API密钥、活动库和旧会话。安装默认本机访问，预置三个暂停自动采集的真实LED信源。移机操作见studio-deployment.md。
