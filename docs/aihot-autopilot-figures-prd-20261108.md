# AIHOT 懒人上线与矢量配图 PRD（Codex Goal 版）

> 日期：2026-11-08。依据：用户当天的要求（“我允许犯错，只需要后续纠正”“要给我懒人选项”“SVG 配图要有一套面向结果的闭环评分”）和 Gemini 的配图分析。与《命题采编 PRD v2（Goal 版）》并行：先做本文的“一键上线”，片段成稿继续按 PRD v2 推进。
>
> 视觉意图稿：`docs/prototype/figure-templates.html`（四个模板已画好，含示例 ALT、图注和质检分）。

## 0. 结论

1. **上线默认从“先拦后发”改为“先发后改”。** 只保留五道全自动过滤：隐私、风险清单、公司禁止项、抄袭、密钥。这五道只删内容，不等人。其余问题自动修，或带着上线，事后在抽查清单里改。
2. **懒人选项分三档：** 人审后上线（默认）、一键上线、全自动上线。一键上线：任何已生成的稿件（包括 MiP v3）点一次就上线；素材池里勾选的素材也能点一次就成稿并上线。全自动：采集完成后，按日上限自动出短讯和短文章并上线。
3. **配图：** 四个参数化矢量模板。模型只给参数，代码负责画图、转 PNG、上传，并写入 ALT 和图注。长文、短文章、升级页每篇至少配 1 张，短讯不配图。特色图每篇单独一个附件，ALT 不重复。
4. **闭环评分：** 上线前算质检分，只决定这张图用不用，不挡文章；上线后按 Google 图片数据算效果分，自动改 ALT、调整模板的使用优先级。
5. **顺序：** 先做一键上线（改动小，做完 MiP 就能由你一键上线），再做配图，最后做全自动上线和效果分。

## 1. 懒人档

### 1.1 三种上线方式

| 档位 | 你做什么 | 系统做什么 | 适用 | 默认 |
|---|---|---|---|---|
| 人审后上线 | 审稿、批准，在 WP 点发布 | 推成草稿 | 全部 | 默认 |
| 一键上线 | 在 Studio 点“直接上线” | 按 1.2 节自动处理，然后直接发布 | 任何已生成的稿件；素材池勾选后“一键成文并上线” | 你在设置里打开后可用 |
| 全自动上线 | 不用操作 | 采集后自动挑选、成稿、配图、发布，按日上限 | 短讯、短文章；长文和升级页要在设置里单独打开 | 关 |

### 1.2 一键上线的处理顺序（全部自动，不等人）

1. 还没回答的确认题按保守写法处理；工程师没回复的题也一样。
2. BLOCK 句：能在同一句或素材里找到出处主体的，自动补上“X says”；找不到的，删掉这句。
3. WARN 不处理。
4. 配图：生成并评分，低于 60 分的图不放。
5. 过五道过滤（1.5 节），命中的句子或条目直接删掉。如果删完后正文不到原来的 60%，这篇改为草稿并记一条，避免发出残稿。
6. 发布到 WP（`status=publish`），同时写入分类、标签、特色图和 meta 描述。
7. 读回：页面返回 200，标题和正文与提交内容一致；不一致就自动改回草稿并记一条。
8. 进入“上线后抽查”列表。

### 1.3 全自动上线

- **触发：** 每天采集完成后执行。短讯攒够 5 条就出一期；短文章取候选池里热度最高的 1–2 条；长文按问题地图里的需求排序挑题，要单独打开。
- **日上限（默认值，可在设置里改）：** 短讯 1 期、短文章 2 篇、长文 1 篇（需单独打开）、升级页 0 篇（需单独打开，因为它会覆盖已有排名的页面）。
- **去重：** 30 天内发过相同主题的不再发，按标题和关键词的相似度判断。
- **总开关：** 设置里的开关和环境变量 `AUTOPILOT_ENABLED` 都为真时才生效。关掉后立刻停止，不留排队任务。
- **为什么要日上限：** Google 的规模化内容滥用政策针对大量低价值的批量页面，日上限加上“每篇至少一张自算图或一张表”，可以降低整站被降权的风险。另外，CSM 试点只有 100 个路由。

### 1.4 上线后纠错（代替上线前的人工关卡）

- **抽查列表：** 一键上线和全自动上线的内容按上线时间排列，每条有三个按钮：没问题 / 改一处 / 下线。下线就是把 WP 文章改回草稿，点一次即可。升级页另有“回滚到上一版”，用 WP 自带的修订记录。
- **节奏建议：** 每周抽查 10 分钟，先看升级页和长文。
- **纠错闭环：** 每次“改一处”或“下线”都要选一个原因：数字错、归属错、过时、语气、其他。每周汇总进周报；同类错误出现 3 次及以上，就改提示词或词典。
- 已上线的内容改过之后，翻译版本按 CSM 自己的规则更新，AIHOT 不处理。

### 1.5 五道自动过滤（任何档位都生效，不需要人）

| 过滤 | 命中后怎么办 |
|---|---|
| 隐私：询盘里的人名、邮箱、电话 | 替换为占位符 |
| 风险清单 v2：同行负面、自家负面、贬损齐普 | 删掉这一条或这一句 |
| 公司禁止项：私有黑名单里的 deny 项 | 删掉这一句 |
| 抄袭：与原文连续 25 个以上英文词相同；原厂图片 | 改写这一句一次，仍相同就删除；不用原厂图片 |
| 密钥和内部地址 | 删除 |

其余情况，包括措辞、WARN、缺工程确认、轻微的事实偏差，都不拦，带着上线，事后改。

## 2. 反过度防御守则（对所有执行者生效）

1. 默认动作是“上线并记录”，不是“停下来等”。
2. 只有 1.5 节的五道过滤可以拦内容，而且只删内容、不等人。
3. 不新增状态、档位、审批步骤或报表字段，除非它能直接减少一步上线操作。
4. 超时或结果未知时，自动重试一次；仍然失败就跳过这一项，其他照常进行。
5. 回执最多 5 行，不写 NOT_RUN、UNKNOWN 这类清单；没做完的事写进“下一步”。
6. 测试只覆盖新增的行为，不为已有能力补防御性测试。
7. 新增规则必须附一个真实发生过的失败例子，且工作量不超过推进工作的 1/5（沿用 D-14）。

## 3. 矢量配图

### 3.1 四个模板

| 模板 | 用途 | 模型给的参数 | 代码负责的部分 |
|---|---|---|---|
| grid-sizer | 尺寸、项目 | 目标尺寸、候选箱体尺寸、点间距 | 行列数、实际尺寸、差值、像素、比例 |
| bar-compare | 功耗、亮度、密度、成本 | 2–6 个条目的名称、数值、单位 | 比例尺、刻度、标签位置 |
| layer-stack | 封装和结构 | 选哪几列（SMD、COB、MiP、GOB） | 结构图形固定在模板里 |
| signal-flow | 控制系统和冗余 | 信号源、端口数、行列数、是否双备份 | 节点和连线的布局 |

画法以意图稿为准：画布 1200 × 675；颜色只用五种（线和字 #13191c、次要 #5c676c、数据 #0a6f75、高亮 #2ce2e8、差值 #b5651d）；数字 24–28 px，最小 14 px；图里只放数字、单位、型号和圈号；右下角是 CHIPSHOW。layer-stack 和 signal-flow 是示意图，模板定稿时请工程师看一次即可，不影响上线。

### 3.2 生成流程

1. 成稿时，在 PRD v2 的片段成稿里新增一种片段 `figure`。模型输出 `{template, params, alt_en, caption_en}`。
2. 代码校验参数：模板存在；每个数值都能在事实表或计算结果里找到；条目数在范围内。
3. 由模板函数渲染 SVG，布局固定，模型不写坐标。
4. 在目标机上用现有的 Chromium（Playwright）把 SVG 转成 1200 宽的 PNG，同时测量文字框，供质检分使用。
5. 通过 WP REST `/wp/v2/media` 上传 PNG，写入 `alt_text` 和 `caption`。WordPress 默认不允许上传 SVG，所以只传 PNG；SVG 源文件保存在 AIHOT 里，以后可以重画。
6. 在正文中插入：`<figure class="cs-figure"><img src="…" width="1200" height="675" alt="…" loading="lazy"><figcaption>…</figcaption></figure>`。

### 3.3 每篇配几张

- 长文和升级页：1–3 张，每个有数字的子问题最多一张。
- 短文章：1 张。
- 短讯：不配图。
- 没有合适的模板时（比如纯新闻），不硬画。文章照常上线，抽查列表里记“缺图”。

### 3.4 特色图（每篇单独一个附件）

- 长文、短文章、升级页：用正文第一张图作特色图。它是独立附件，ALT 自然不会重复。
- 短讯：每期上传一份底图副本，ALT 写本期内容，例如“LED Display Brief No. 12: MiP packaging, compact LED power supplies and the 84th OBIE Awards”。
- 验收：任意两篇文章都不共用同一个特色图附件。

### 3.5 ALT 和图注

- **ALT：** 10–18 个英文词，写成“图件类型 + 主体和对比对象 + 一个关键数值或条件”。不以 image of 开头；同一个词最多出现 2 次；和正文主题一致。
- **图注：** 1–2 句，写结论和适用条件，末尾注明来源（Calculated by Chipshow、厂商名或标准名）。
- 解释性文字只放在图注和 ALT 里。CSM 翻译图注即可，不用重画图。

## 4. 闭环评分

### 4.1 上线前：质检分（每张图 0–100，由代码计算）

| 项 | 分值 | 怎么算 |
|---|---|---|
| 数据一致 | 30 | 图里每个数字都能在事实表或计算结果里找到：全部找到得 30，否则得 0 |
| 渲染 | 25 | 文字框不重叠、不越界（在浏览器里测量）；最小字号 ≥14 px；对比度 ≥4.5:1 |
| ALT 和图注 | 25 | ALT 的词数和格式正确、没有堆词；图注写了来源 |
| 文件和唯一性 | 20 | PNG ≤300 KB；与已发布的图做感知哈希比较，不能太接近，防止重复出图 |

**怎么用：** ≥80 分直接用；60–79 分自动修一次（缩短标签、减少条目、重写 ALT）再评分，修完只要 ≥60 分就照用；低于 60 分不放图，文章照常上线，抽查列表记“缺图”。

### 4.2 上线后：效果分（每周按页面计算）

- **数据：** 在 GSC 效果报告里，搜索类型选“图片”，维度选“网页”，每周导出一次 CSV 导入系统；以后也可以改接 Search Console API。按页面计算图片曝光、图片点击和点击率，同时记录这个页面在网页搜索里的曝光和点击。
- **时间窗口：** 上线满 28 天后开始计算。
- **自动动作：**
  1. 页面网页曝光 ≥100、图片曝光却为 0：自动重写一次 ALT 和图注，不重画图。
  2. 再过 28 天仍为 0：换模板或改参数，重画一次。
  3. 每月按“每张图的平均图片点击”给模板排名。连续两个月排最后的模板，降低使用优先级，并请 Claude 改版式。
  4. 图片点击前 5 名的图，把它们的 ALT 和参数作为提示词里的范例。
- **周报：** 加一节“配图成绩单”，列出本周新增的图、质检分分布、各模板的图片曝光和点击，以及前 5 名和后 5 名。
- **说明：** GSC 的图片数据按页面汇总，不按单张图。一页有多张图时，按页面计算。

## 5. 对 Gemini 配图方案的处理

| Gemini 的写法 | 结论 | 说明 |
|---|---|---|
| 四个模板，模型只给参数，代码排版，转成 PNG，文字放图注 | 采纳 | 已画成意图稿 |
| 每篇必须至少 1 张 | 修正 | 没有合适的模板就不硬画，文章照常上线 |
| ALT 为空时要补齐才能推草稿 | 修正 | ALT 自动生成，不挡上线 |
| 500 × 1000 mm 箱体按 12 × 3.5 拼成 6.0 × 3.5 m | 修正 | 3.5 行要用半高箱；示例改为 500 × 500 mm，12 × 7 正好拼满 |
| Codex 读不到 WP 生产库，需要你把原文贴给它 | 不需要 | Codex 已经通过 WP REST 读到 6098 的正文，认证和媒体上传都验证过 |
| 尺寸指南提纲（首屏答案、视距与像素速查表、询价六项、三条 FAQ） | 作为 6098 子问题的参考 | 视距数值要引用公开可查的出处。AVIXA DISCAS 是付费标准，只能引用公开的摘要，或者改用像素密度计算 |
| 20 个钩子的数字来自 9 月核验包 S01–S16 | 接受 | Codex 使用时附上原文链接 |

## 8. Goal（贴给 Codex，分两段）

### Goal A：一键上线与矢量配图（现在做）

```text
目标：让运营可以把任何已生成的稿件，或素材池里勾选的素材，一键发布到官网，并自动配上矢量图和 ALT。出了错，靠事后下线和回滚纠正。

先读：Drive 目录 11.08-AIHOT-Claude执行计划v2 里的《AIHOT 懒人上线与矢量配图 PRD》和 figure-templates 意图稿。在 PR #17、#18 的基础上做；PRD v2 的片段成稿继续并行。

完成定义：
1. 设置页有三种上线方式（人审后上线 / 一键上线 / 全自动上线），默认是人审后上线；有总开关，并能按内容类型设日上限。
2. 稿件页和素材池都有“直接上线”。点一次后，系统按 PRD 第 1.2 节自动处理确认题、BLOCK 句、五道过滤和配图，发布到 WP，读回一致后进入“上线后抽查”。在真实站点上用 WP 的私密状态（private）完整跑一次：发布 → 读回 → 下线 → 回滚。
3. 抽查列表里每条都有“没问题 / 改一处 / 下线”。下线点一次即生效；升级页可以回滚到上一版；纠错原因可选，并进入周报。
4. 四个矢量模板按意图稿的画法，从 JSON 参数渲染 SVG，转成 1200 宽的 PNG，上传 WP 媒体库并写入 alt 和 caption；正文插入带 width 和 height 的 figure。
5. 每张图都有质检分和四个分项分。≥80 分直接用；60–79 分自动修一次；低于 60 分不放图，文章照常上线。自动测试覆盖：图中数字与事实一致、文字不重叠且不越界、ALT 词数。
6. 特色图每篇单独一个附件：长文、短文章、升级页用正文第一张图；短讯每期上传一份底图副本，并写本期专属的 ALT。
7. 真实样例：6098 升级稿配 grid-sizer 图和像素密度 bar-compare 图，MiP 稿配一张 layer-stack 图，附 PNG、alt、caption 和质检分。
8. CI 全绿；本轮没有新增任何需要人等的步骤；超时自动重试一次。

只在这些情况停下来问人：WP 账号没有发布或上传媒体的权限；需要你打开一键上线或全自动上线；CI 失败且当天修不好。

完成或停下时，交 5 行回执，附样例图和 CI 链接，放回同一个 Drive 目录。
```

1. 想开摆的时候，在设置里打开“一键上线”或“全自动上线”（默认是关的）。
2. 每周花 10 分钟看“上线后抽查”。
