## 0. 一页结论

1. **控制软件教程要正面竞争，靠的是实机一手资料，而不是发更多文章。** LinsnLED 估算 2,915/月的流量几乎全部来自非品牌词，由四块构成：控制系统软件与配件（253）、消费级显示比较（4 页占 30.6%）、多语种故障排查、图片包（959）。用户已决定在控制软件教程上正面竞争，能赢的唯一依据是工程多品牌实机的截图、步骤和报错处理；模型只负责整理和翻译，不补写内容。
2. **守住已领先的题材，并抢先占下没人做的。** 齐普在户外/DOOH 领先（199 vs 97），交通 VMS 是独有题材（23 vs 0），这两块要继续守住。用电与电费、亮度法规、物流装柜、防雷这些客户关心的题目还没有竞品占位，是成本最低的增量。
3. **AIHOT 多花的 token 值不值，取决于选什么信源。** 普通新闻源，“定时检索+摘要”的基线同样做得好。只有三类信源离不开 AIHOT 的跨日记忆：版本源（软件/固件、规格书、手册）、条件源（电价、法规、标准、运价）和需求源（脱敏询盘、GSC、Semrush、AI 回答观察）。P0 把信源投入集中在这三类，新闻源少而精。
4. **询盘台账脱敏后进系统，按四类角色建客户画像。** 画像只用于选题排序和写作定向，不当事实源；公开稿里的公司能力事实只能来自批准过的公司资料。
5. **P0 交给 GPT 做的事：** 扩充信源（停用状态，预览核验后加入）、导入脱敏台账并建画像、建问题地图、做“今日值得处理”选题卡、导出社媒帖文。中英双语视频周报和下载中心放到 P1。验收看推荐题采纳率和更新旧页机会数，询盘与 AI 引用只作观察。

### 1.3 Linsn 的“先发”由什么构成

- **控制系统：** 诺瓦 ViPlex 软件页估算 195。“vi-plex”（480/月）排第 1，“viplex express”第 2，HUB75B 第 1，LEDStudio 第 3，“novastar vx1000 manual”第 1，VX4S 第 3。站内直接挂了诺瓦 ViPlex 手册 PDF。EagerLED 的同类页面有 VX1000 Pro vs VX1000、RCFG 下载、LEDStudio 下载、TU15 集成指南。
- **消费级比较：** 3D vs IMAX 466、UHD vs QLED 172、Hz vs FPS 129、LCD vs LED 125，四页合计占 30.6%。
- **多语种排障：** 西语黑斑页 69、法语闪烁页 32 等；“rayas negras en la pantalla”9,900/月，Linsn 排第 10。
- **搜索特色结果：** 图片包 959（32.9%）、AI 概览 351。
- **含义：** 控制软件要正面竞争，就必须在“实机操作、版本更新、报错可复现”上超过对手。消费级比较不跟。

### 1.4 客户会关心、但还没人占位的题材

以下按关键词规则匹配，没有逐页阅读，需要人工复核。

- **运营成本：** “digital billboard annual operating costs breakdown”720/月，齐普排第 31；“led billboard cost”齐普排第 5。
- **用电与电费：** 矩阵里的相关词大多是灯具类的 lumens/watts；显示屏用电和电费类的词没有竞品占位。
- **亮度与招牌法规：** 五站基本都没有内容。
- **交通 VMS：** “variable message sign”320/月，齐普排第 4，其他四站没有。
- **物流装柜、防雷浪涌、太阳能供电：** 搜索量小，但询盘里有需要（见 1.5），属于“不热门但有用”。
- **水损与防护：** “led screen water damage”880/月，Linsn 第 9、洲明第 12。
- **COB / MiP：** “cob led display”260/月，Linsn 第 17；“COB”这个大词被洲明占着。

### 1.5 客户需求证据

样本是询盘台账 10-12 至 10-16 一周的 88 条，未按客户去重。

- **地区：** 中非拉美 34、欧洲 25、亚太 15、北美 12。
- **需求文字提及（可重叠）：** 系统配套与安装 24、分销与集成合作 13、交付与运输 12、现货与海外仓 5。

### 3.3 S2 控制软件与固件（版本源，教程和下载中心的依据）

- **产出：** 出现新版本时生成选题卡“教程需要更新/新增”；从 P1 起同时更新下载中心的登记。
- **教程正文：** 工程上传实机截图、操作步骤、版本号、报错与处理办法。模型只整理和翻译，不补写菜单、参数或步骤（D2、D8）。

## 4. 客户画像与问题地图

### 4.1 脱敏台账导入

- **建议字段：** week（ISO 周）；region（中非拉美、欧洲、亚太、北美、其他）；channel（Facebook、WhatsApp、网站、MIC、邮件等）；role（D6 的四类，加“未知”）；product_direction；scenario（户外招牌、DOOH、交通 VMS、租赁舞台、室内商显、体育等）；need_tags（现货与海外仓、交付与运输、系统配套与安装、分销与集成合作等，可多选）；question_rewrite（把一句原问脱敏改写）；grade（台账的 A/B/C 评级）。
- **不导入：** 客户名、公司名、联系人、邮箱、电话、网址、报价金额、项目地址、聊天原文。
- **导入校验：** 只要发现邮箱、电话号码、网址这类模式，整批拒收，并报告行号和字段；系统不自动“清洗”后入库。
- **增量导入：** 可以多次导入，每批记录导入时间和行数，运营可以整批撤回。不再导入时，画像显示最近一次导入的日期。

### 4.2 画像（只做聚合）

按“角色×地区×场景”聚合需求标签和高频原问，只展示计数和代表问法。计数口径要写明：按登记提及计数，可重叠，未按客户去重。

用途是选题排序和推荐理由。写作时只提供聚合描述（这篇写给哪类读者、他们卡在哪一步），不提供单条询盘。D3 提到的“让 AIHOT 认知公司情况”，由 P1 的“公司资料卡”承接，内容是批准过的公司能力事实；在此之前继续沿用现有 CAMOS 站点规约。

### 4.3 问题地图（选题的基本单位）

每个问题一条记录，字段包括：问法（客户原话的风格）、角色、场景、维度（场景、部件、工况、费用、维护、供货、控制软件，即吴总说的“基向量”）、已有页面 URL（必须是实际读到的，未知就留空）、依赖的条件数据（例如 EIA 表 5.6.A 的某个数据期）、相关信源、需求证据（台账计数、GSC、Semrush）。

首批题目来源：吴总 V4 的 3+5+4 题，Semrush 的 20 项优先行动，台账的需求标签，以及按工程实机整理的控制软件教程清单。规模大约 30–50 题，由运营维护。

## 5. 选题推荐：“今日值得处理”

### 5.1 触发规则

| 触发  | 条件  | 建议动作 |
| --- | --- | --- |
| A 变化 | 版本源或上游源出现变化，并且命中了一个已有页面的问题 | 更新已有页面 |
| E 版本 | 控制软件或固件出了新版本 | 更新或新增教程（P1 起同时更新下载中心） |
| B 需求 | 画像里反复出现，问题地图里却没有页面 | 新写解释文、教程或工具页 |
| C 缺口 | GSC 有展示但排名靠后，或者 Semrush 里竞品进了前 10 而我们缺页 | 补强已有页面，或新写 |
| D 新闻 | 新鲜的发现源消息，并且能说清影响哪类客户 | 短讯（可以附“采购要多问的 3 件事”） |
| 其余  | —   | 仅留参考、HOLD 或 SKIP |

### 5.2 卡片内容

沿用 PRD 的四行：变化是什么；证据在哪（原文链接、日期、版本）；为什么值得处理（画像和需求证据）；建议动作加建议渠道（Blog、社媒、视频周报）。

运营的决定有三种：采纳（创建采编任务）、否决（必须填理由）、稍后再看。

### 5.3 数量与排序

- **每周上限：** 和审核产能一致（D15：5–15 件）。没有值得处理的，就显示“暂无新增，保留原计划”。
- **排序（建议，未定具体数值）：** A、E 排在最前，其次是需求证据重复的 B，再是 C，最后是 D；同一类内按画像里的需求计数排。前两周只记录采纳和否决，用这些标注来校准，不凭感觉定分数门槛。
- **不为选题卡另起模型调用：** 变化检测、去重和条件比对都由程序完成。只有“影响哪类客户”这一句判断可以走现有的 Flash 渠道，并经过回执和预算。

## 6. 内容产品与渠道

### 6.1 Blog（英文、零汉字，沿用现有导出）

包括短讯、技术解释文、控制软件教程（实机）、工具页（如电费试算，沿用吴总 V4 的样板）和已有页面的更新。

### 6.2 社媒（P0）

Facebook/LinkedIn 英文帖文由已批准的 Blog 稿派生，带链接回到 Blog。中文社媒稿（D12）单独审核、单独导出。

### 6.3 视频周报（P1，中英双版）

从周报里选 3–8 条（不够就不出）。每条 10–20 秒口播，来源和日期上屏，配分镜，参考橘鸦逐条带时间码的格式。另外从问题地图的解释类题目里出“AI 矢量科普”选题建议。

### 6.4 下载中心（P1；用户已决定在本站托管，D13）

AIHOT 只负责登记和监测，不负责网站托管。每个文件登记厂商、软件、版本、发布日期、官方来源 URL、获取日期、文件大小和 SHA-256。官方出了新版本时生成更新卡；原厂提出异议时，运营可以一键标记下架并导出变更。再分发授权、文件过时、被篡改这三项风险，用户已知并接受。

### 6.5 同行与品牌规则

同行只报事实，不评价（D10）。厂商的说法写成 According to [来源]；参数属于原厂及其条件，不能挪成齐普的产品事实（沿用 editorial-direction）。

## 7. 验收（D16）

- **推荐题采纳率：** 采纳和否决的比例，以及否决理由的分布。
- **更新旧页机会数：** 用同一批信源，统计基线（定时检索+上期摘要+同一模型）没发现、AIHOT 发现了的“已有页面该更新”的机会数，以及其中实际完成更新的数量。
- **询盘与 AI 引用：** 已发布 URL 关联到的 GSC 点击、可识别的询盘、固定问题集里的引用。周期长，只观察，不作门槛。
- **继续记录但不作门槛：** 人工分钟，回执里的 token 和费用（未知不记为 0）。
- **试产期（建议）：** 4 周，与吴总 V4 的节奏一致。

## 8. 风险与边界

- **控制教程没有实机资料：** 那就只是改写手册，反而伤 GEO。没有实机材料的教程任务直接 HOLD。
- **下载中心再分发：** 风险用户已接受（D13）。
- **中文公开：** 只限视频和社媒（D12）。
- **画像：** 不含能识别个人或公司的信息，只以聚合形式进入写作（D5）。
- **同行：** 只报事实（D10）。
- **网络：** 本会话无法核验外部信源。GPT 所在的环境需要能访问这些站点，或者由运营在目标机器上做预览。

## 9. 给 GPT 的开发需求与指令

### 9.1 全局约束（摘自 AGENTS.md 和现有文档，必须遵守）

- **前后端边界：** 前端（apps/web）只通过 HTTP 读 apps/api；数据库、模型调用和密钥只在后端；公开出口只走 packages/backend/src/publication/。
- **模型调用：** 读者打开页面不触发模型调用；模型只在任务里调用，并经过 providers/receipts.ts 的回执和预算熔断。
- **安全阀：** COLLECT_ENABLED、MODEL_CALLS_ENABLED、FEISHU_*_ENABLED、INDEXNOW_SUBMIT_ENABLED 保持关闭；测试只连本地假服务。
- **数据库迁移：** 放在 database/migrations/，用新文件名（当前最新是 0095）；每个文件只放一条可在线执行的语句；索引用 CONCURRENTLY IF NOT EXISTS。
- **配置与提交：** 新的环境变量写进 .env.example；不提交 .env、密钥、.data/ 和询盘原始文件。
- **改完要跑：** npm run typecheck；DATABASE_URL=postgres://127.0.0.1:5432/aihot_test npm test；npm run build -w @aihot/web && node --test apps/web/tests/*.test.ts。
- **写法：** 匹配周围代码的写法，只定义正在用的抽象；复用已有能力，例如 sendFile、LLM_BASE_URL、Studio 的任务和回执。
- **命名：** 对外不使用 AIHOT 的名字和 Logo。
- **什么时候停下来问用户：** 需要真实客户数据样本；需要改动 D1–D18 中的任何一条；信源预览失败、需要改选入口。

### 9.2 P0 任务

#### G1 扩充信源配置

- **目标：** 把 3.2–3.5 里标为 P0 的信源加入 industry/sources.json，全部设为 enabled:false、site_fulltext:false、syndicate_fulltext:false。
- **步骤：** 每个候选先用现有后台的信源预览（docs/sources.md 的“先预览再创建”）核对标题、链接、日期和去重。预览失败的不写进配置，把失败原因记在 docs/led-source-verification.md。复用 rss 和 web_list，不新写采集器。
- **同步更新：** 在 industry/led-source-plan.json 增加对应的 candidate 和 directions，保持它原有的 schema；docs/led-sources.md 更新接入顺序。
- **验收：** tests/sources.standalone.test.ts 覆盖新配置“停用、全文关闭”；预览结果写进核验文档。不启用，也不 seed 到生产。

#### G2 脱敏询盘导入与客户画像

- **目标：** 后台上传 CSV（字段见 4.1），校验通过后入库；画像页按“角色×地区×场景”聚合。
- **数据：** 新增最小的表（例如一个批次表和一个信号表），每个迁移文件一条语句；批次可撤回，撤回时删除该批次及其所有行。
- **校验：** 缺必填字段、出现未知枚举值、命中邮箱/电话/网址模式时，整批拒收，并返回行号和字段；不自动改写。
- **接口：** 放在 /api/admin/studio/ 下（上传、列表、撤回、画像聚合），沿用 adminHandler 和 CSRF。
- **测试：** 只用合成样本，不用真实询盘；覆盖 PII 拒收、撤回后画像计数归零、画像接口不返回 question_rewrite 以外的单条字段。

#### G3 问题地图

- **目标：** 在 Studio 里维护问题（字段见 4.3），支持导入初始清单 JSON。已有页面 URL 只能由运营填写，或者从实际读取的结果填入。
- **数据：** 用最小结构，和信源 id 关联；条件数据用文本引用即可。不建知识图谱。
- **种子数据：** 提供 industry/question-map.example.json，用 4.3 的首批来源拟定，运营确认后再导入。示例里的内容不当作真实事实。

#### G4 “今日值得处理”选题卡

- **目标：** 按 5.1 的触发规则，从素材池、版本变化、画像和导入的 GSC/Semrush 数据生成候选卡。卡片有四行内容，加建议动作和建议渠道。采纳即创建现有的 studio_tasks；否决必须填理由，并记录下来。
- **约束：** 卡片以程序规则生成为主；需要模型的“一句影响判断”走现有渠道、回执和预算。同一个素材版本不重复出卡。每周上限在设置里可调，具体数值由运营在 D15 的 5–15 件范围内设定。
- **GSC/Semrush：** P0 只做 CSV 导入，不接 API。
- **测试：** 重复输入不重复出卡；原文版本变化后重新出卡；否决理由必填；采纳后生成任务，并保留对卡片的引用。

#### G5 社媒帖文导出

- **目标：** 已批准的 Blog 稿可以派生 Facebook/LinkedIn 英文帖文（含字数、链接、来源与日期），也可以派生中文社媒稿。帖文和 Blog 稿绑定同一个原文版本，原文变化后需要重审。
- **规则改动：** assertPublicEnglish 仍然只约束 Blog 的公开英文字段；中文社媒稿用单独的字段和单独的审核状态（D12）。site/editorial.ts 和 docs/editorial-direction.md 同步改写。
- **测试：** 中文社媒稿不能混进 Blog 导出；Blog 导出仍然零汉字。

#### G6 验收记录

- **目标：** 在现有审稿和介入统计旁边增加：卡片的采纳数、否决数和否决理由分布；“更新已有页面”卡的数量和完成数。基线对照用一个手动记录的字段（基线是否也发现了）。
- **约束：** 不新增运营必填台账；未知就显示未知。
