## 3. 创意审查：从“过审”到“抓人”

现在的问题是：文章写给编辑门看，不是写给读者看。为了过归属检查，正文堆满“据该公司称、条件未知”；一句话短讯被字数上限切得只剩公关标题。修正方法是，把出处放进标签和表格的来源列，正文直接说事，并给每类内容规定前 5 秒读者能看到什么。

### 3.1 三类内容的 5 秒首屏

| 类型 | 首屏结构 | 要达到的效果 |
|---|---|---|
| 短讯（一期） | WP 标题由前 2–3 个钩子组成；正文顶部是“In 5 seconds”三条；每条依次是：标签、钩子标题、1–2 句事实、可选的“Why it matters”、可选的“Go deeper”内链、来源和原文日期 | 扫一眼就知道今天有什么；点进常青页，流量留在站内。版式见意图稿 v2 |
| 短文章（蹭热度，400–700 词） | 钩子标题；首段两句写清“发生了什么”和“反转或影响”；然后 3 个要点、1 张自制图或表；结尾内链到常青页 | 借热点拿点击和社媒传播 |
| 长文（解决真实问题） | 标题按搜索意图写；首屏是 40–60 词的直接答案、关键数字或对比表、适用对象；再往后是正文、用询盘原话写的 FAQ、更新日期、工程师署名审核 | 被搜索和 AI 回答直接引用，读者读完能做决定 |

### 3.2 钩子库（冲击力优先，每个钩子都有事实锚点）

| 模式 | 英文示例（花括号是变量） | 事实锚点 |
|---|---|---|
| 主语加动词 | MEAN WELL shrinks LED display power: new 200–400 W UDP series | 原文标题或首段 |
| 规模 | A {N} m² screen just went up at {venue} | 数字来自原文 |
| 反差 | Brighter isn't always better: {reason} | 正文首段用出处或工程师的话讲清原因 |
| 代价 | The spec most LED quotes leave out, and what it costs you | 正文点名这项参数并说明代价机制，经工程师确认 |
| 悬念 | What happens to an LED wall when the power blinks? | 首屏给出答案 |
| 对决 | COB vs MiP: which one survives a rental tour? | 正文有对比表 |
| 地标 | {Landmark}'s new screen: what it takes to light up {N} m² | 地标新闻原文 |
| 首发 | Just announced: {vendor} {product}, and the 3 specs that matter | 原文 7 天以内 |

- **规则：** 钩子里的数字、名词和动作，都要能在正文前两句找到出处。禁止编数字；禁止“首个、最强、颠覆”之类的词，除非原文这么说并写明是谁说的；禁止贬损同行或齐普；禁止制造恐慌；标题许诺的内容必须兑现。
- **长文标题：** 按搜索意图写，关键词放前面，不超过 60 字符。冲击力放到封面和社媒文案里。
- **做法：** 每条短讯或每篇文章出 3 个候选，标出每个钩子靠哪句事实撑住，由运营选一个。

### 3.3 流量与 GEO 引擎

| 引擎 | 做法 | 目标 |
|---|---|---|
| 泛流量信源 | 加新闻搜索 RSS，关键词表由运营维护，例如：LED screen stadium、LED billboard、video wall、jumbotron、DOOH、digital signage、MicroLED、LED wall concert、virtual production LED volume、transparent LED。每周把采纳率低于 20% 的关键词换掉 | 素材量够每 1–2 天出一期 |
| 常青页内链 | 建一张页面登记表（URL、对应问题、关键词、最后更新）。短讯和短文章按关键词建议内链，长文绑定一个询盘问题 | 把热点流量导向常青页和产品页 |
| 点击率回路 | 每周用 GSC 导出数据，找出曝光 ≥100 次、但点击率低于同排名常见水平的页面，各给 3 个标题和描述候选；你挑一个，改 WP，4 周后复看 | 直接提高点击，这是最便宜的增量 |
| GEO 基础 | robots.txt 放行主要 AI 爬虫和 Bingbot；提交 sitemap；验证 Bing Webmaster Tools，开 IndexNow；首屏放答案、表格、FAQ、来源、更新日期和审核人。每月拿 30 个买家问题，在 ChatGPT、Perplexity 和 Google AI 概览各问一次，记录是否引用了齐普 | 被 AI 回答引用。只做观察，不作为验收 |
| 社媒 | LinkedIn 帖子的前两行放钩子；每期短讯出一条帖子文案，交给发帖人 | 把站外流量带回官网 |

### 3.4 长文的信息增益（至少满足两项，否则改写成短文章）

- 询盘原题（脱敏），用客户自己的说法写进标题、首段或 FAQ。
- 工程师答疑或引语，署名或写明职务。
- 自家项目案例或现场照片。
- 决策表或算例，例如按观看距离选间距、估算功耗。

**点对点维护：** 页面登记表记录“问题 ↔ URL ↔ 最后更新日期”。有新信息时生成一个“更新任务”。给销售的定制私发版放到第 3 周以后再做。

## 4. 交付能力审查：砍掉什么，保留什么

### 4.1 交付卡住的五个原因

1. **没有客观闸门。** CI 从未运行，PR 只能靠 Agent 在缺工具的环境里自证，于是只能 HOLD。
2. **完成标准做不完。** GSC 增长、AI 引用、北极星连续两周达标，被写进了工程的完成定义。
3. **规则只加不减。** 每轮审查（包括我的 v4.1、v5 和 Chat 参谋）都在加状态和例外，没有人删。

## 6. A2A 交接与审校

### 6.1 Codex 回执（每个阶段结束交一次，不超过 5 行，另附 JSON）

- **出货：** WP 草稿或预览链接、PR 链接、CI 链接。
- **数字：** 短讯期数和条数、长文篇数、采集的源数和条数、每篇必须确认的提醒数、审稿分钟数。
- **卡住：** 卡在什么，在等谁（你、IT 或 WorkBuddy）。
- **下一步：** 一句话。
- **请你决定：** 编号列出，没有就写“无”。

JSON 格式见 docs/handoff/aihot-exec-a2a-20261108.json，字段与 aihot-agent-handoff/1.0 兼容。

### 6.2 Claude 审校（每份回执一次，结论不超过 10 行）

| 方面 | 检查 |
|---|---|
| 创意 | 抽 5 个钩子，看有没有事实锚点、够不够抓人、有没有贬损；抽 1 篇的首屏，做 5 秒测试（答案、数字、读下去的理由）；抽 1 篇长文，看信息增益是否 ≥2 项 |
| 底线 | G1–G5 各抽查 1 个样例 |
| 代码 | 读 1 个已合并 PR 的差异，确认 CI 链接是绿的 |
| 结论 | 只有两种：通过，或改这几处（逐条写出）。要加新规则，必须附一个真实发生的失败例子 |

### 6.3 只有四种情况需要停下来问人

1. 任何公开动作：在 WP 点发布永远由你来做，系统不发布。
2. 需要你或 IT 提供的东西：WP 应用密码、GSC 导出、主题特色图尺寸、询盘问题清单、工程师的时间。
3. 要删除目标机上的已有数据。
4. CI 失败，当天修不好：如实报告，不跳过测试。

## 7. 风险与对冲

| 风险 | 对冲 |
|---|---|
| 冲击力标题与 Google“不夸张”的要求有冲突 | 钩子必须由正文首段兑现。4 周后，如果短内容点击率高但读完率很低，就把尺度调低 |
| 新闻搜索 RSS 噪声大 | 用风险清单、去重和人工勾选兜底；每周把采纳率低于 20% 的关键词换掉 |
| WP REST 被安全插件拦截 | 退回复制包（已有），每篇多 5 分钟人工 |
| 翻译插件不兼容区块 HTML | 文字不放进图片和 CSS 伪元素；第一期发布后，看一个其他语言的页面 |
| 素材版权 | 只用自己写的摘要加原文链接；封面自制，不用原厂图片 |
