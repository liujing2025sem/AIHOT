# AIHOT 产品 PRD v1.1｜从信源变化到值得处理的内容动作

执行依据：[Grill 决议与开发需求](aihot-grill-decisions-20261103.md)。原件日期为 2026-11-03；实施发生在 2026-11-02 America/Los_Angeles。第 2 节 D1–D18 是用户决定，本文不重新解释或投票。v1.0 历史保留在 Git bccc20f。

## 产品结果

AIHOT 为 Chipshow Blog 及社媒提供可追溯的选题、采编和更新工作台。它超出“定时检索”的价值，应由持续记住材料版本、关联已有页面、利用聚合需求与搜索缺口来证明。健康检查、产出数量和测试数量不能代替业务结果。

对照基线是：定时检索/抓源 + 上期摘要 + 同一个 DeepSeek 模型 + 人工发布。不能用无历史、无规则的弱定时任务证明优势。当前尚未完成同批材料的基线实测，增量价值保持 UNKNOWN。

## 用户与分工

- 运营：维护问题与实际 URL，选择每周 5–15 件审核产能，采纳/否决/稍后再看，补事实证据并批准稿件。
- 工程：提供软件版本、实机截图、真实操作步骤、报错处理及测试条件。模型不得补写缺失的实机过程。
- Studio：独立调用 OpenCode 供应的 deepseek-v4.1-flash，保留任务、回执、预算及结果复用，不依赖聊天 Agent 替写。
- Codex：主策、后端执行、集成与回执。WorkBuddy：跨 harness 安装、运行、采编验证。Opus：仅评审关键框架和用户体验，按需看证据，不承担日常采编。

5. 可报道未证实信息，标题、摘要、正文均保留消息状态、出处和原日期；后续确认、否认、更正必须一致。

7. 内容 D1–D10 / W1–W8 及逐项确认继续有效。这里的内容规则 D1 与 Grill 决议 D1 属于不同编号体系。

## 选题规则

| 触发 | 可复核输入 | 内容动作 |
|---|---|---|
| A 变化 | 同 URL 前后可读正文出现相关段落变化，并命中已有页面的问题 | 更新旧页；差异仅是待核线索，不声称语义已证实 |
| E 版本 | 软件/固件版本线索，有近期原日期或真实正文变化 | 教程提案；实机资料不足先 HOLD |
| B 需求 | 聚合登记反复提及，问题尚无已有页 | 待补证据的新解释文、教程或工具内容任务 |
| C 缺口 | 导入 GSC 有展示且排名靠后，或 Semrush 前 10 与缺页问题关联 | 补强实际页面或新写；Semrush 是估算 |
| D 新闻 | 近 7 天、非未来日期的 LED 商显主题材料 | 短讯候选；正文未齐先待补证据 |

排序为 A、E、B、C、D，同类按可用需求计数；本期不合成一个总分，不为卡片另起模型调用。其余保留参考，允许“暂无新增，保留原计划”。日期不明不会伪补抓取日；初次补全旧归档正文不会伪装跨日变化。选择建议并不等于批准其事实。

## 事实与写作边界

采纳资料不足的建议会创建原有的待补证据任务，绑定完整原文后继续同一任务。更新已有页还须绑定该页正文；软件教程须绑定人工登记的 external + first_party 工程来源。这个来源标记由运营负责，程序不能替代对截图、版本和步骤真实性的人工确认。上述不足在模型调用和回传落稿前检查。

GSC/Semrush 采用提供的 CSV 模板或支持的列名导入，不接 API。询盘字段及严格枚举以下载的模板/字段说明为准；不替用户自动清洗、推断身份。代表问法只用于内部聚合页；写作任务只有计数和聚合定向。画像从来不是齐普的公司或产品能力证据。

社媒与 Blog 各自批准。父 Blog 改稿、撤销批准或来源修订，旧社媒的批准/导出失效，需从重新批准的 Blog 派生。英文社媒也保持英文；中文只走中文社媒出口。社媒初稿是无需额外模型的派生起点，不宣称已经按平台完成创意改写。

## 验收与试产

验收主看采纳数/否决数与理由分布、旧页更新机会及实际完成人工登记。采纳率分母为采纳+否决，稍后与未处理不计。基线未对照保持未知；不新增强制运营台账。人工分钟、回执 token 与费用继续记录，未知不记 0，不作为本轮继续门槛。询盘和 AI 引用仅观察。

建议先运行四周：首周由运营确认真实问题和已有 URL，启用少量核验源，工程补一份实机材料；每周用相同输入对照强基线，记录其是否也发现更新机会。若没有增量，先调整信源与问题关联，不增加模型层数或卡片数量。
