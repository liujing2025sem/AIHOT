# AIHOT 原工程工作台接续

## 本轮目标

在 PR #24 的原工程上保留完整业务能力，接入用户已认可的定方向、审正文、配封面、手工交付体验。内容继续由原采编、分段生成、私有品牌规则和付费回执链路生产。

## 事实基线

- 起点：8c0e72cc330b87b3fa7bee6f4f37f62531fe70a3，codex/four-chains-20261110。
- 原架构：React Router Web 只经 HTTP 访问 API；PostgreSQL、模型、密钥与任务在原后端。
- 已存在素材、选题、事实、范围与标题选择、片段生成、审稿、配图、社媒派生和发布历史。
- 现有 Sites 试用使用独立存储，尚未连接原实例；不能将独立示例编辑器称为原系统部署。
- 原本机的 6098 第 2 版仍待用户审核，回执 16/17 未知；本轮不重新生成、批准、送稿或发布这些记录。

## 实施范围与依赖

1. 保留原导航与业务对象，在原项目内提供工作台入口及四步文章处理视图。
2. 增加部署级手工交付能力，统一限制 WP 写入入口和任务执行，保留原模块、历史及只读恢复。
3. 复用当前版本批准校验和 HTML/Markdown/JSON 导出，不把下载记作发布。
4. 以原事实、选择、分段生成和规则包验证内容链路，不以演示数据代替真实产出验收。
5. 不新增并行业务库；本轮默认不改数据库结构。新功能先检查已有服务和存储方式。

实施补充：封面候选使用原 PostgreSQL settings 与原 AIHOT_DATA_DIR，图片内容按哈希存储，候选另绑定 ALT/图注身份。上传只增加候选；采用不改变正文批准。成品确认在原批准事务校验后，绑定正文版本及选定封面。ZIP 包含英文正文、SEO、图片与本地路径引用，不标记发布。原导出增加可选版本参数，拒绝旧页面下载另一版成稿。管理员可配置 ADMIN_USERNAME，原会话、限速与 CSRF 继续使用；最低密码长度依用户明确需求统一为 11 字符。

私有写作规则包、原模型配置与原实例可达性属于部署依赖。缺失时保留真实原因，不用通用提示词替代，也不展示模拟生成进度。

## 最小证明与反例

- 手工模式：API 调用和已排队任务都不能向 WordPress 发送写请求；只读恢复继续可用。
- 原有发布模式：原模块行为保留，只有明确开启的部署可使用。
- 标题、小节、选中范围进入原生成请求；未选片段不生成，锁定原文保持逐字节一致。
- 事实未保存不能越过；人工补充不得自动标为已查证。
- 未批准或版本不匹配不能导出成品；重复相同确认不升版；未知付费回执不重发。
- 导航包含素材、选题、任务、稿件、社媒、页面与效果、连接及运行记录的真实入口。
- 桌面与窄屏检查完整阅读、证据定位、错误状态与键盘操作。

## 设计计划与复核

页面白 #FFFFFF、工作台灰 #EDF2F7、正文黑 #000000、工作蓝 #2C4FC4、待核橙 #955300、错误红 #B02B35。中文操作使用系统中文无衬线；英文成稿使用 Iowan Old Style / Palatino Linotype / Georgia 衬线，正文约 66–72ch。左对齐，列表承载队列，完整稿件承载阅读。

唯一突出设计是稿中判断与原文证据同屏对应。原能力保留全局入口，四步只处理当前文章。复核后去掉概览大数字、相同卡片墙、通用登录口号、装饰大写眉题及灯珠背景。英文衬线仅用于真实成稿，避免整站变成报纸模板。
