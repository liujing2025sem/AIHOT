## 已落实的五组变化

### 1. 默认阅读完整英文稿

完整 HTML/Markdown 正文采用服务器派生的 `body_html`，通过现有管理员 GET 返回；阅读与保存采用同一次读取的稿件版本。源稿继续保存在 `document.body_en`，保存动作原样使用编辑字符串。阅读视图显示已保存版本，存在本地修改时直接标明；点「编辑源稿」恢复原始输入。

手机 DOM 顺序调整为正文在前、问题和操作在后。上方保留待处理问题入口，正文后可跳回问题区；问题定位沿用原来的字符串偏移，并可返回原触发按钮。表格可聚焦、在正文容器内横向滚动。

删除旧的三段截断预览、重复的展开状态和嵌套稿纸边框。阅读、HTML 导出及手工包共用 `renderReviewedBody`，没有新增解析依赖。

### 2. 控件和键盘可用

共享输入采用独立 `control-border`，卡片与分隔线继续使用原颜色。后台控件边界对白底的计算对比度为 3.81:1。手机文字保持 16px；焦点使用 outline。请求限额名称关联服务与时间周期，审计筛选具备可见标签和提交按钮，评测样本使用原生展开按钮。

### 3. 配置草稿保持在当前任务内

信源运行状态变化保留名称和 JSON 草稿；显式保存后采用服务器规范化结果。模型渠道使用既有 Radix Tabs，非活动面板保持挂载并隐藏，切换期间输入和密钥留在组件内存。保存后同步规范化结果并清空密钥输入。

交叉审查实际发现并修复：只重排 JSON 键顺序时，服务器返回值可能与旧配置相同；显式保存现在直接接收该返回值，让界面恢复已保存状态。

### 4. 选图完成后先看结果和下一步

当前采用的封面排在候选首位，「检查交付文件」前置。已有封面时上传区收为「添加或替换封面」；首次无封面时展开。原生 disclosure 保持控件挂载，文件、ALT、图注的原有保护继续生效。相同文本、相同语义的活跃通知去重，减少动态效果时直接显示最终状态。

### 5. 名称与当前操作一致

- 新闻材料：侧栏、页标题与工作台入口一致。
- 买家问题：工作台列表和全部入口明确对象。
- 选题与旧页升级：侧栏、工作台入口、页面标题一致。
- 模型连接、上线后抽查：入口与页面标题一致。
- 5–12 条短讯模式收起不参与合成的目标页、内容类型及单篇动作；回到 1–4 条时保留先前输入。
