# CSM issue 草稿：接住 AIHOT 发布的 Blog 文章

> 由 Claude 根据 AIHOT 执行计划 v2 起草，供用户在 CSM 项目里直接提交，可自行删改。数字是预估，来源写在每条后面。

## 背景

AIHOT 会往 chipshow.com 的 WordPress 推英文文章草稿，由用户手动发布。发布后的多语言版本统一由 CSM 生成；AIHOT 不做任何翻译开发。

## AIHOT 这边的输出

- **页面类型：** WordPress 文章（posts），不是产品页。
- **分类：** 两个。`LED Display Brief`（slug `led-display-brief`）放短讯和短文章；长文和升级后的常青页放在现有的指南类分类。消费级显示的内容另带标签 `consumer-display`。
- **正文结构：** 短讯是固定结构的 HTML 区块（外层 `div.cs-brief`；每条一个 `section.cs-item`，含标签、`h2` 标题、正文段落和来源行）。所有文字都在 HTML 里，没有放进图片、CSS 伪元素或脚本。样例见 AIHOT 仓库的 `docs/prototype/daily-brief.html`。
- **特色图：** 4 张无字品牌底图，按分节选用，不需要翻译。
- **更新方式：** 发布后不改 slug；更新文章时在同一个 URL 上改。

## 预计量

- 每周：短讯 2–4 篇、短文章 2–4 篇、长文和升级页 1–3 篇，合计 5–11 篇（来源：AIHOT 执行计划 v2 第 6 节）。
- 按每篇一个 `/de/` 路由算，每月新增约 20–45 个路由。

## 与 CSM 当前容量的关系

- 2026-10-30 的独立审查给出的试点上限：100 个路由、500 个任务、主文档 8 MiB；当时主文档约 7.23 MiB（7,584,881 bytes）。
- 按上面的量，2–5 个月内会碰到路由上限，主文档可能更早吃紧。

## 希望 CSM 这边做的

1. 先处理容量（CSM 计划里的 N07 量测、N08 范围调度、N09 容量与缓存），再大量接入 Blog 文章。
2. 验证 Blog 文章模板和 `.cs-brief` 区块的翻译与回读；目前验证过的是产品模板，以及文章 9509 的一次翻译。
3. 给出接入方式：哪些分类或标签自动进入翻译，单篇怎样手动加入或排除。

## 不在本 issue 范围

AIHOT 的内容生成、WordPress 草稿推送和审稿流程，由 AIHOT 项目负责。
