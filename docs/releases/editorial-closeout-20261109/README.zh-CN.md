# AIHOT 采编收口更新包

本包继续使用 React 编辑台。主要操作仍是选材料、看成稿、处理提示、交付。五项代码衔接已经补齐，真实文章验收在原实例进行。

## 运营会感知到的变化

| 场景 | 现在的操作 |
|---|---|
| 稿子还有错误 | 可以保存已修改部分，刷新后继续；批准和交付仍检查问题。 |
| 更新尺寸指南6098 | 交付区显示原地址与改动清单，默认只推独立影子预览稿，不改线上原页。 |
| 做一期短讯 | 在今日选稿选5–12条材料，点“合成一期短讯”；去重后需至少5个独立事件，结果是一篇待审合集。 |
| 有可安全处理的建议 | 卡片先展示要删的英文原句，再点采纳；重新检查剩余问题。当前支持有确定边界的删句，复杂改写仍手工处理，不补造参数。 |
| 中文落后于英文 | 中文标旧，英文为当前稿；按英文核对后才能批准。未自动调用翻译。 |
| 看上游动态 | 新闻类型决定14或30天窗口；厂家名字本身不让项目或市场新闻变成30天。 |
| 配图 | 待审页可预览既有信息图和ALT/图注；实际上传复用既有模块。无合适图或渲染失败保留说明，不凭空制造图形事实。 |

短讯正文有分节、三条速览、每条的出处与原日期。可选内链只能取自已登记的本站页面。窗口之外的常青参考资料仍可用于长文，不被删除。

## 两点必须知道

**影子稿只能预览。** 不要在 WordPress 直接发布影子稿，否则会成为新文章。覆盖6098是另一项动作，需要再次确认原页、基线和改动片段。当前界面保留预览为默认出口。

**本包没有真实业务数据。** 原有6098、MiP、凭据、黑名单、数据库都不在包里。没有实际操作原实例，也没有真实采集一期新闻或把文章发上官网。测试数据不能用于报道。

## 维护人接续

先读 `DEPLOYMENT.md`，再读源码中的 `docs/LIVE.md` 与 `docs/handoff/aihot-editorial-closeout-20261109.json`。

代码与Web构建包含于 `source/`；精确版本、文件列表和哈希见 `RELEASE.json`。最终CI结果见同批交付回执。没有Windows便携运行时及 `node_modules`，不得整包解压覆盖正在使用的安装目录。

项目没有改变默认模型、采集和发布开关；已有明确开启的一键上线模式仍按其独立规则运行。此次五项验收走人审路径，不增加新的公开授权。
