# 原工程工作台增量部署

## 适用基线

本次改造从 PR #24 的 `8c0e72cc330b87b3fa7bee6f4f37f62531fe70a3` 接续。它继续使用原 Node / PostgreSQL / worker / React Router 工程。工作台入口为 `/admin/workbench`，原 `/admin/studio`、命题、审稿与各项管理入口保留。

本次没有修改依赖锁文件或数据库迁移，不复制、替换或清空已有稿件。不要将 Sites 独立试用库作为原业务库导入，也不要将本机私有 API 暴露到公网。当前 Sites 运行环境与原 Node 服务的部署方式不同，站点链接不能证明原后台已经连接。

## 升级次序

1. 核对目标原实例的源码、端口及进程归属，停止本实例应用，避免停止其他安装。已有 Windows 运行包沿用 `tools/local-runtime.mjs` 与原启动持有器。不要移动 node_modules 工作区链接。
2. 先备份原受影响文件、Web build、业务库、原私有配置及 `AIHOT_DATA_DIR`。账户修改前的凭据配置单独留在私有备份中，不进入通用安装包。确认 6098 的稿件 ID、版本、状态、正文指纹，回执 16/17 的状态与次数。备份只留用户控制的私有位置。
3. 应用本次分支相对基线的差异，重建原 Web。保留原私有环境、数据库、模型渠道和业务附件。私有写作包继续使用 `AIHOT_WRITING_RULES_ROOT` 指向的已校验目录，不能提交到公共仓库。
4. API 与任何实际运行的 worker 都设置 `STUDIO_DELIVERY_MODE=manual`，保留 `WP_DRAFT_PUSH_ENABLED=false`。该部署能力独立于数据库旧发布设置，能阻止残留发布队列和客户端写入。只设置 Web 进程不生效。不要为本次部署启动此前关闭的定时 worker。
5. 在原私有凭据配置中设置用户要求的 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD`。用户名启用后，后端同时核对账户名和密码；旧会话失效，需要重新登录。运行服务最低密码长度为 11 字符。密码不进入通用包、命令行历史、日志或 Git。保留已有 SESSION_SECRET；不要从另一个实例复制会话。
6. 模型与采集保持本轮原有关闭状态，按原启动流程执行迁移核对并启动 API/Web。原实例采用用户的账户登录，检查 `/api/admin/studio/capabilities` 返回 manual，再打开 `/admin/workbench`。

## 本机验收

- 记录登录成功、真实原稿列表、原功能入口可达、刷新保存和原稿版本；截取不含凭据的界面。
- 6098 保持原第 2 版待审，不代批、不重新生成、不推影子稿。回执 16/17 保持未知且不重发。
- 用明确标识的独立测试稿验证封面候选、采用、成品确认和下载。不得使用待审生产稿替代测试稿。
- 上传只增加候选；同一图片配不同 ALT/图注也形成独立候选。采用不撤销正文批准；正文变更使成品确认失效。
- 下载的 ZIP 包含英文完整预览、正文 HTML、Markdown、SEO 信息、选定封面、原参数配图和交付指纹。图片使用本地引用。下载不改成已发布，不写 WordPress。
- 普通导出保留，带 version 参数时严格核对所见版本。旧页面不能悄悄下载另一版。
- 检查原未知模型回执不会因超过 30 分钟自动放行。这里只核对已有状态，不重发旧调用。
- 实际文章质量需以完整真实任务、选定范围、事实与来源、原模型响应及回执验收。测试夹具和规则包加载不算文章验收。

## 文件与恢复

封面状态存于原 PostgreSQL 的 `settings`，键为 `studio.cover:<draft id>`；图片位于 `AIHOT_DATA_DIR/studio-covers`，内容哈希校验后读取，管理员认证后才可下载。候选的图片与说明分别绑定，图片采用原子保存。原数据备份应同时包含数据库与此目录。

恢复代码时先停止本实例应用，按增量清单恢复旧文件及 Web build，移除本次新增的源码文件。不要删除原稿、回执或封面附件。因为未增加迁移，纯代码回退不需要回灌业务库。手工交付限制在旧版本中不存在；回退期间保持原所有 WP 写入设置关闭，核对旧发布队列再启动。

旧基线的生产启动与登录要求至少 12 字符密码，本版按用户指定凭据统一为 11 字符。回退旧认证代码时，同步恢复升级前的私有凭据配置并保留原会话密钥；不要把新配置的 11 字符密码直接留给旧版本启动。模型、采集和 WordPress 写入仍保持关闭，旧会话或账户登录结果必须重新核验。

本文件是安装与核验步骤，不能作为“原实例已经部署”的回执。实际执行结果需另附时间、提交、端口、运行模式、关键业务状态和测试结果。
