## 1 · B0 品牌隔离铁律（最高优先，违反即失败）

**只为 `https://www.unishineled.com/` 工作。**

- **绝不**提及、引用、继承、对比、转述、依赖：`chipshow.com` ／ `chipshow.eu` ／ `chipshowledusa.com`。
- **绝不**使用任何 Chipshow 产品、规格、项目、认证、专利、客户、保修、制造主张、品牌身份或内部文件。
- 即使产品与应用主题看起来相似，**也把 Unishine 当作独立品牌**。
- **共享所有权、制造关系或产品表面相似，都不构成事实迁移授权。**
- 某条声明**只有 Chipshow 证据** → 标 `blocked`，从可发布文案中剔除（`S2`）。

> 与 `skill-a` 的 `T13-01` 同源，但这里是**执行口径**：逐条可判。

## 4 · B3 问题簇层（A4）→ 页面职责层（A5）→ Brief 门

> **编号定位**：A4／A5 出自主题簇规划里「问题簇与决策链」那一层。那层的实物是本包 `references/topic-clusters.md` —— 9 个簇（UNI-C24～C32），每簇已写好 Core decision、Entry question、Decision chain 四步、Topic boundary、Collision rule。**A4 ＝ 把这层已有内容取全；A5 ＝ 在其上指派这一页的职责。** 与 `skill-a` 的章节 A4／A5 **不是同一套编号**。

**顺序不可颠倒**：

1. **问题簇层（A4）** 定义完整问题簇：子问题、权衡、证据、买家下一步。
2. **页面职责层（A5）** 指派页面类型、**唯一主任务**、重叠边界、商业承接下一页。
3. **Brief** 只取**该页所需的决策链片段**，不取整个簇。
4. **过门之后才起草。**

| 状态 | 动作 |
|---|---|
| `approved_to_draft` | 只起草已批准的页面与唯一主任务 |
| `conditional` | 只在批准的条件下进行，并把条件显式写出 |
| `blocked` | 完整起草前停下，报告未决事项 |
| **缺 A5** | 新 URL／临时选题／可能重叠 → **停下，请求页面责任复核** |

**两条禁令**：

- **不得把关键词自动变成文章。**
- **不得把整个 Topic Cluster 抄进每一页** —— 一个簇可支撑多页，**每页必须保留一个清晰的职责**。

细则读 `references/content-brief-gate.md`。

## 6 · B5 证据台账（Unishine-only）

每条实质声明必须落入四类之一：

| 类别 | 允许的支持来源 |
|---|---|
| `verified` | **现行 Unishine 目录**或**官方 Unishine 页** |
| `externally_verified` | **现行第三方一手来源**（标准／事件／法规），**非竞品** |
| `editorial` | 有用的非事实性解释 |
| `blocked` | 缺失・冲突・过期・动态・**仅有 Chipshow 支持** |

**永不编造**：规格、认证、测试结果、工厂数字、保修、可得性、价格、MOQ、交期、库存、客户、案例、比较优势。

**严格保留单位与型号范围。** 目录与网站冲突 → 走 `S5`，展示冲突并请求确认。

## 8 · B7 先计划后写作

紧凑计划须含七项：

1. 读者问题与**承诺的答案**
2. 唯一页任务
3. 主意图与支撑问题
4. 工作 H1 与 H2–H3 结构
5. **每节所需的证据**
6. 内链去向
7. 读者下一步

**方向仍在讨论中时，不得写代码、schema 或可发布文案**（`S6`）。**不得隐藏假设。**

## 9 · B8 写作规范

**读者**：经销商、代理商、OEM/ODM 买家、AV 与系统集成商、租赁公司、项目采购团队（按任务取用）。

**偏好**：选择逻辑、项目约束、生命周期考量、已验证的产品细节 —— 而非泛泛推广。
**避免**：关键词重复、无支撑主张。
**不强制** CTA 或联系信息；**非明确要求不加 FAQPage schema**。

### 9.1 写作铁律 W1–W10

| # | 规则 | 判据 |
|---|---|---|
| **W1** | 价格范围也必须有证据 | 不写 `$/m²` FOB 价、控制卡单价、钢构报价 —— 这些不是 catalog 数据。宽泛价格范围同样须有来源／时间／配置／计价口径／适用范围；**无证据时只解释影响因素，不生成价格区间**；**不以竞品价格代替 Unishine 证据**；参考文章只学表达，不抄内容与句式 |
| **W2** | 参考文章只学写法 | 可借鉴结构（有证据的价格说明 ＋ 因素拆解 ＋ 组件清单）；句式、例子、叙事角度**必须原创**；品牌边界以 `agents/unishine-brand-expert.md` 已定义内容为准；**未定义的额外品牌事实须请用户确认**，不以主题簇或旧备份填补（`S7`） |
| **W3** | 长尾关键词从第一稿就嵌入 | 动笔前拿到关键词清单并标注每个词落在哪段；**不得写完再补**；8–10 个长尾词合理分布在 intro／body／H2／conclusion。**适用范围**：博客／指南类文章的编辑惯例，**来源未记录、无样本支撑**；产品页／方案页**不按词数执行**。缺关键词清单时，用 `G4` 的 6–10 个子问题代替定位，并标为假设，**不得自造搜索词**。 |
| **W4** | 产品提及 2–3 处，90/10 铁律 | 全文 **90% 教育内容、10% 品牌内容**；产品在知识对比或技术方案讨论中自然带出；**不单独开产品专栏段落**。**适用范围**：同为编辑惯例，**不是可校验指标**——「90/10」按篇幅人工估，不写成 PASS/FAIL；产品页、方案页不套用「2–3 处」上限。 |
| **W5** | 不确定断言 → 省略并标 `blocked` | 不用模糊措辞替代；缺证据、来源冲突、适用范围不明的断言从公开正文省略、编辑备注标 `blocked`；缺失信息影响核心结论 → 先补证据（`S8`）；步骤／参数列表／对比表**逐项核验**，缩成一句或加条件词**不能补救**事实缺口 |
| **W6** | 每句断言都能找到出处 | 数据来自 Unishine E-Catalog 2026／产品参数表，逐项核对型号、适用条件、单位、范围及具体来源位置；IP 等级定义可依据适用标准解释，但**定义不证明某产品达到该等级**；刷新率、寿命等数值**不是通用行业标准**，每个数值须有型号／适用条件／来源；**自己推演的判断不写** |
| **W7** | 段落能短不长 | 一段说清一个点；Conclusion 一段话；复杂概念拆成 2–3 短段 |
| **W8** | 禁用词清单 | 不写 `best` / `No.1` / `leading` / `cheap` / `cheapest` / `innovative` / `revolutionary` / `cutting-edge` / `premium`（无依据时）/ `solution`（过度使用时）。改写：高品质 → 点名组件品牌；便宜 → `factory-direct pricing`；领先 → 用参数说话 |
| **W9** | 不用对比式表达、不写抽象话 | 不用 `A is like B` / `X is half of Y` / `underused asset` / `real value emerges` 这类比喻或抽象总结；直接说这是什么、为什么重要、怎么做；**每句落地到一个具体动作或事实** |
| **W10** | 破折号尽量不用 | 英文破折号（—）在 B2B 文章里显得松散；用句号断句；需要插入补充信息时用逗号或括号 |

## 10 · B9 GEO 结构（SEO ＋ 生成引擎可见性）

目标：既赢排名，也能被 AI 答案（ChatGPT、AI Overviews、Copilot）引用 —— 降低 AI 理解、抽取、信任、引用本页的成本。

| # | 规则 | 判据 |
|---|---|---|
| **G1** | TL;DR 模块 | 在 H1 与 introduction 之间放 **50–100 word** 直接回答，作为**独立摘要块**（不是 intro 第一句）；用条件化表述（`often suitable` / `can` / `may`）；**须与 Meta Description 区分**（C1） |
| **G2** | Answer-first 开头 | 先答核心问题再给背景；避免 `LED displays have become increasingly important…` 式开场 |
| **G3** | Answer Unit 结构 | 核心 H2/H3 按 `Question → Direct Answer → Why → Exceptions → Evidence` 组织 |
| **G4** | Query Fan-out | 起草前列出主问题隐含的 **6–10 个子问题**（场景／风险／边界／数字／定义／比较）并覆盖；把每页定位成**决策支持页**，不是关键词页 |
| **G5** | 证据分层 | 每个数字与强声明分类：A 自有数据｜B 厂商／标准／第三方（`According to IEC…`、datasheet、行业报告）｜C 经验判断（**须保持条件化**）；**绝不发布看似有来源却无来源的数字**。**C3**：不自动生成 `Based on Unishine installation experience…`，经验论断须逐项对应来源、条件和范围 |
| **G6** | 决策型 FAQ | 围绕**购买决策**写（成本、认证、维护、安装、供应商筛选、保修），不写通用问题 |
| **G7** | Author/Reviewer | `Reviewed by Unishine Technical Team` ＋ 公司经验声明 —— **C2：不统一默认添加**；仅当技术团队**真实审阅已获确认且获准署名**时才加，否则省略 |
| **G8** | 区域化场景 | 允许**区域级**（Europe / North America / Middle East）与**场景类型级**（rental stage、control room、retail storefront）；**永不点名具体城市、场馆或客户** |
| **G9** | 商业链接链 | 每篇文章向 Unishine 产品／方案页内链，**不做孤岛** |
| **G10** | 速查表（可选） | 场景 × 推荐规格表，**仅在数字经 Unishine 技术/产品数据确认后**才允许；否则标 `pending data` 并省略 |

## 11 · B10 交付前审阅

### 11.1 九项逐条检查

| # | 检查项 | 不过怎么办 |
|---|---|---|
| 1 | 每处实质事实都用 **Unishine 已批证据** | 标 `blocked` 并剔除，或补证据 |
| 2 | **无任何 Chipshow 名称、URL、产品、事实、措辞或身份** | 删除并全文复扫 |
| 3 | 页面任务、意图、读者与语言一致 | 回 `B4` 重核 |
| 4 | 与重叠的 Unishine 页面有**明确边界** | 回 `B3` 请求页面责任复核 |
| 5 | 无支撑的最高级与隐藏占位符已移除 | 删除；占位符须显式标出 |
| 6 | 各节回答不同的买家问题 | 合并或移位 |
| 7 | 内链与 FAQ 可用 | 补齐或删 |
| 8 | **输出不得呈现为已发布** | 改回 `draft_for_review` |
| 9 | 未获明确且单独批准 → 不动发布／CMS／跟踪配置 | 停下等批准 |

### 11.2 写作与审稿长期规则（2026-09-17 用户确认）

1. **先判断段落必要性，再润色**｜每节回答「读者看完知道什么、能做什么」；答不出优先删并或移位，不靠换词保留。（品牌资质类允许目的为理解品牌事实／证书范围／事件意义，不强行导向采购。）
2. **看不懂时的排查顺序**｜段落是否必要 → 前提是否交代 → 因果是否成立 → 术语是否解释 → 英文是否清楚；连续两次反馈**停止逐句修补**，重查整节，不预设原因。
3. **证据逐项对应**｜每条证据对应具体论断／适用条件／范围；**来源真实不等于支持该句**；条件词不能补救错误因果或无来源概括。
4. **三项分别验收**｜事实核验／读者理解／文件一致性**分开验收**并报告未核事项；字数、链接、FAQ、Schema 通过不能证明技术正确或问题清零；**用户认可正文不等于技术团队审阅**。
5. **核心前提改动后**｜检查全文依赖该前提的解释、建议、总结及摘要／表格／FAQ／Schema，不只检查改动句；回读前一段后两段核对因果、回指、重复。
